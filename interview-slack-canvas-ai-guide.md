## 🎨 Part 1 — Slack Canvas: Prototyping, Iteration, and GA

### The Challenge
- Slack needed a document space directly embedded inside channels to keep files, checklists, and documentation from getting buried in conversation history.
- The editor needed to feel fluid, support markdown shortcuts, render rich cards (like unfurled links), and handle collaborative typing from hundreds of users concurrently.

### Technical Decisions & Prototyping
1. **Block-Based Document Model:** Instead of a single giant HTML document, Canvas was structured as a flat list of independent "block" nodes (paragraphs, headings, todos, attachments). This isolation allowed us to update specific DOM blocks when modified, preventing page-wide re-renders.
2. **Optimistic Operations:** When a user types or toggles a checkbox, the local UI updates instantly (optimistic state transition) while the operation is queued and synced with the backend collaboratively.
3. **Link Unfurling Cards:** Link items map automatically to structured data cards, rendering Figma files, GitHub PRs, or Jira tasks inline, preventing context switching.

### Key Performance Target
- **Keystroke Latency Budget:** Keep local edit updates under **16.67ms** (one frame at 60Hz) to prevent text lag.
- Achieved an average latency of **8.4ms** (p95 = 24ms), keeping document editing smooth even during heavy parallel edits.

## 🤖 Part 2 — Slackbot AI: Real-Time Stream Integration

### SSE streaming over WebSockets
- To make Slackbot AI useful, it needed to answer natural-language questions (e.g. *"Summarize this channel"* or *"List my action items"*) with low latency.
- Waiting for the entire LLM response to complete on the server took 5-10 seconds.
- **The solution:** Server-Sent Events (SSE). The server streams tokens (words) as they are generated by the LLM. The frontend parses this stream and appends words dynamically using a custom cursor renderer.

### SSE Parser Logic
- The client establishes a POST connection to the stream endpoint.
- Reads chunks using a `ReadableStreamReader` and a `TextDecoder`.
- Decodes chunk lines starting with `data: `, extracting token JSONs, and updates the chat state dynamically.
- Handles connection aborts cleanly if the user navigates away or cancels the prompt.

## ⚙️ Part 3 — Engineering, Code Reviews, & Tests

### Quality and testing frameworks
- **Cursor Offset and Selection Tests:** Dynamic rich-text editors frequently break cursor positioning when formats (bold, link cards) change. We wrote tests using React Testing Library to ensure cursor offsets remain unchanged during structural changes.
- **Node Sanitization:** Contenteditable inputs can carry malicious HTML scripts. We implemented strict parsing and escaping utility functions to sanitize inputs before rendering.
- **PR Review Philosophy:** As a senior engineer, PR reviews are about mentoring and raising quality. I focus on deriveable states, error boundaries, keyboard focus traversal, and ensuring components degrades gracefully when network failures occur.

## ❓ 25 Interview Q&As

#### Q1: What is Slack Canvas and what was your role in launching it?
> *"Slack Canvas is an interactive, collaborative document workspace embedded directly inside channels. As a Senior Frontend Engineer, I worked on prototyping the initial block-based document model, iterating on visual rendering performance, and launching the editor to General Availability for millions of daily users."*

#### Q2: Why did you choose a block-based document model for Canvas?
> *"A single giant document model requires re-rendering the whole page on edits, causing visible lag. A block-based model treats paragraphs, checklist items, and files as individual nodes. This isolates updates: editing a single block only updates that node's DOM element, keeping the editor fast and responsive."*

#### Q3: How did you achieve a keystroke latency under 16ms for Canvas?
> *"We decoupled document validation from the typing thread. Typing locally updates an optimistic react-state immediately. Heavy tasks like markdown rendering, link parsing, and saving are debounced and processed in background micro-tasks, ensuring typing is never blocked."*

#### Q4: What is local optimistic rendering in a collaborative editor?
> *"It means showing local user edits immediately without waiting for server confirmation. When you check a todo box, the checkbox turns green instantly. In the background, we fire a mutation request to the server. If the server rejects it (e.g. conflicts), we rollback the UI state to match the server."*

#### Q5: How do you handle edit conflicts when two users type on the same Canvas block simultaneously?
> *"We use operational transformation (OT) algorithms. When conflicts happen, the server reconciles the edits and broadcast changes to clients. On the frontend, we merge incoming changes into the block queue while maintaining the local cursor position index."*

#### Q6: How does Slackbot AI stream text responses in real-time?
> *"We use Server-Sent Events (SSE). Instead of waiting for the full LLM response, the backend streams text tokens (words) over a persistent connection. The frontend reads these tokens using a text decoder and appends them to the chat state, giving the user a visual typing effect."*

#### Q7: What are Server-Sent Events (SSE) and why use them over WebSockets for AI chat?
> *"SSE is a lightweight, one-way push protocol over standard HTTP. Since AI chat only requires the server to stream response tokens (client input is a simple single request), SSE is simpler to set up, handles reconnects automatically, and has lower infrastructure overhead than WebSockets."*

#### Q8: How does your SSE parser handle broken chunks or connection failures?
> *"We use a decoder buffer. Chunks can arrive split in the middle of a JSON string. Our parser buffers partial strings and only runs `JSON.parse` when it detects a newline (`\n`) boundary, which signals a complete SSE event line. If the socket closes prematurely, we fallback to a retry wrapper."*

#### Q9: How did you prevent XSS vulnerabilities in the Canvas contenteditable blocks?
> *"We never bind raw strings to `dangerouslySetInnerHTML`. We run all user inputs through a sanitization function that escapes HTML characters (`<`, `>`, `&`, `"`, `'`). Rich elements like links or stickers are rendered as structured React components, never raw HTML."*

#### Q10: How do you test cursor positioning in a React contenteditable component?
> *"We write unit tests in React Testing Library. We simulate typing events, manually set DOM selection offsets using `window.getSelection()`, trigger actions like formatting text to bold, and assert that the cursor selection offsets remain correct post-render."*

#### Q11: What is your PR review checklist for junior engineer contributions?
> *"I check: (1) Accessibility: are focus traps managed and ARIA roles correct? (2) State structure: is there redundant local state? (3) Graceful degradation: does it use error boundaries? (4) Testing: does it have unit tests for edge cases? (5) Typing: no use of 'any'."*

#### Q12: Why is checking for derivable state important in reviews?
> *"Redundant state leads to bugs. If you store both `items` and `checkedCount` in state, they can drift. Instead, store only `items` and calculate `checkedCount = items.filter(i => i.checked).length` dynamically during render. It's cleaner and prevents mismatch bugs."*

#### Q13: How did you measure editor crash rates during the GA rollout?
> *"We wrapped the Canvas editor in a React Error Boundary. When a render crash occurs, the boundary catches the error, renders a fallback card, and fires a crash metric with the stack trace to our log aggregation servers. This allowed us to monitor our 99.98% crash-free target."*

#### Q14: How does a keystroke latency tracker metric work?
> *"We register a keydown timestamp using `performance.now()`. When React commits the resulting state change to the DOM, we calculate the elapsed time. If this duration exceeds 16.67ms, it means we dropped a frame, and we log a latency drop warning."*

#### Q15: What is link unfurling and how is it integrated into Canvas?
> *"When a user pastes a URL (e.g. Figma or Jira link), our parser detects it and asks the server for the URL metadata. The server returns a structured preview (title, description, image). The frontend then replaces the plain text URL block with a rich visual card component."*

#### Q16: How do you design components to be responsive across desktop and mobile?
> *"We use flexbox layouts, relative sizing, and logical layout properties. Mobile renders the document inline without sidebars, and shifts actions to bottom sheets. Desktop uses side-by-side panels and floating toolbars. We share the same core block model across both."*

#### Q17: What was the biggest technical risk in the Canvas launch?
> *"Memory usage on large documents. Millions of blocks would overwhelm the browser's DOM tree. We mitigated this by virtualizing the block list: we only render blocks currently visible in the user's viewport plus a small buffer, keeping memory usage constant."*

#### Q18: How do you work collaboratively with designers on visual quality?
> *"We use shared design tokens (variables for colors, spacing, typography). Designers configure them in Figma, and they are compiled directly to our JS theme objects. This ensures that what the designer draws matches the code layout exactly, with zero manual conversions."*

#### Q19: How did you ensure Canvas was accessible (a11y) to screen readers?
> *"We ensured keyboard navigation was robust. Users can navigate blocks using arrow keys, toggle checklist items with the Spacebar, and activate links using Enter. We also bound correct ARIA labels and live region alerts so screen readers announce checklist state changes."*

#### Q20: What was the roll-out cohort size for GA?
> *"We rolled out progressively: 1% of workspaces first, then 10%, 25%, 50%, and finally 100%. This progressive rollup allowed us to monitor server loads and catch edge-case rendering crashes before they affected our entire user base of millions."*

#### Q21: What is the Page Visibility API and why does the client use it?
> *"It tells us if a tab is currently active or backgrounded. When backgrounded, we throttle canvas synchronization and disconnect AI SSE sockets to save system memory and battery power for the user. We reconnect immediately once the tab becomes visible again."*

#### Q22: How do you write tests for network failure cases in Slackbot AI?
> *"We mock network requests using MSW (Mock Service Worker). We write tests where the AI stream endpoint returns a 500 error or terminates abruptly mid-stream, and verify that the frontend displays a helpful retry banner instead of hanging or crashing."*

#### Q23: Why is error boundary isolation critical in Slack?
> *"Slack is a single-page application. If a minor component like an emoji reaction crashes, we don't want it to freeze the entire workspace. Error boundaries catch the error locally, render a retry icon for that specific card, and keep the main messaging interface functional."*

#### Q24: What is the most rewarding part of shipping features at Slack scale?
> *"The impact feedback loop. Knowing a keystroke latency reduction of 5ms saves hours of collective waiting for millions of users daily. Seeing engineers and product teams use Canvas to plan their launches is incredibly satisfying."*

#### Q25: How do you balance feature development speed with code quality?
> *"By establishing clear Definition of Done standards. A feature is not 'done' when it works locally. It is done when it is fully typed, covered by unit tests, visually regression checked, and verified for keyboard accessibility. This upfront investment saves weeks of bug-fixing later."*
