### Thuật ngữ
- Kỹ thuật dùng agent (agentic engineering): cách làm phần mềm bằng việc giao việc cho các AI agent viết code thay vì tự gõ hết.
- Năng suất cao / làm song song nhiều việc (high throughput multitasking): chạy nhiều agent cùng lúc để hoàn thành nhiều task song song.
- Trình ghép terminal (terminal multiplexer, ví dụ tmux, Herder): công cụ chia một cửa sổ terminal thành nhiều phiên/tab, có thể chuyển qua lại và giữ các phiên chạy nền.
- Firstmate (thuyền phó): agent "quản lý" duy nhất mà người dùng nói chuyện; nó điều phối các agent khác. Cũng là tên repo mã nguồn mở của Kun.
- Crewmate (thủy thủ): agent "công nhân" do firstmate tạo ra để thực hiện một task cụ thể, mỗi cái chạy trong tab terminal riêng.
- Fleet (đội tàu): tập hợp các dự án/agent do firstmate quản lý.
- Điều phối (orchestrate) / cử đi (dispatch): firstmate chia việc và giao task cho crewmate.
- Pi: một coding agent chạy trong terminal, dùng được nhiều nhà cung cấp model và có thể mở rộng bằng extension.
- Claude Code: coding agent của Anthropic chạy trong terminal.
- Harness: "vỏ" agent bao quanh model (Claude Code, Codex, Pi, Cursor...), cung cấp công cụ như đọc file, chạy lệnh.
- Codex: coding agent của OpenAI; có sẵn công cụ tạo ảnh.
- AGENTS.md / CLAUDE.md: file hướng dẫn đặt trong repo, agent đọc khi bắt đầu để biết quy ước dự án.
- Lệnh gọi công cụ (tool call): mỗi hành động agent thực hiện như đọc file, chạy lệnh shell.
- Chuỗi suy nghĩ (chain of thought): phần lập luận trung gian model hiển thị trong lúc làm.
- Extension "calm" (`/calm`): extension Pi đi kèm firstmate, ẩn tool call và chỉ hiện con thuyền báo agent đang chạy.
- Hạn mức (quota): lượng sử dụng còn lại trong gói thuê bao của mỗi nhà cung cấp model.
- quota-axi: công cụ của Kun hiển thị quota các gói thuê bao; có TUI cho người và CLI cho agent.
- TUI (text user interface): giao diện dạng bảng/màn hình trong terminal dành cho người dùng.
- CLI (command line interface): giao diện dòng lệnh, ở đây output dành cho agent đọc.
- `crew-dispatch.json`: file quy tắc chọn harness + model cho crewmate theo loại task.
- Định tuyến model (model routing): chọn model phù hợp cho từng loại task.
- Nguyên nhân gốc (root cause): lý do thật sự gây ra lỗi.
- Voice input: nhập prompt bằng giọng nói thay vì gõ.

### Chỗ người mới dễ kẹt
- "Chỉ nói chuyện với một agent" → firstmate không tự viết code cho mọi task; nó là agent điều phối, tạo các agent khác (crewmate) trong tab terminal riêng và giao task cho chúng. Người dùng chỉ ra lệnh và xem kết quả qua firstmate.
- "Clone repo rồi chạy agent trong đó là xong" → setup đơn giản vì repo firstmate chứa sẵn file hướng dẫn, skill và config để agent tự biết vai trò điều phối; bạn vẫn cần cài sẵn các harness (Pi, Claude Code, Codex...) và có tài khoản/thuê bao.
- Herder vs tmux → cả hai cùng loại công cụ; crewmate được tạo dưới dạng tab/phiên mới trong multiplexer, nên mới thấy chúng ở panel bên trái.
- Tên model (Fable, Opus 5, Grok 4.5/4.6, GPT 5.6 Sol, Kimi K3, Astra, Luna, Sonnet) → đây là các model ở thời điểm quay video; điều cần học là nguyên tắc chọn model theo loại task, không phải tên cụ thể.
- Harness khác model → cùng một model có thể chạy trong nhiều harness (ví dụ Grok trong Cursor hoặc Pi). Chọn harness quan trọng vì công cụ đi kèm khác nhau (Codex có tạo ảnh).
- Vì sao chọn model theo quota → với nhiều gói thuê bao, dùng model còn dư quota giúp không lãng phí tiền đã trả và tránh bị chặn khi hết hạn mức.
- Ẩn tool call có nguy hiểm không → Kun vẫn bật lại được bằng `/calm` khi cần; ý tưởng là giảm tải nhận thức để tập trung vào quyết định, chứ không phải bỏ qua kiểm tra.
- "Kế hoạch đã có sẵn" → Kun thường lên kế hoạch trước (lưu lại trong dự án), sau đó mới giao cho crewmate triển khai; tách giai đoạn lập kế hoạch và giai đoạn thực thi.
