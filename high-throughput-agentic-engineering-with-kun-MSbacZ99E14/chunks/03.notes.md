### Thuật ngữ
- Second mate (thuyền phó thứ hai): một phiên first mate phụ, được giao sở hữu một mảng (domain) công việc, ví dụ một app cụ thể; tự quản lý crewmate, memory và instructions riêng.
- Charter (phạm vi trách nhiệm): toàn bộ "bản điều lệ"/vùng việc mà first mate chịu trách nhiệm; second mate nhận một phần của nó.
- Crewmate (thủy thủ): agent làm một việc cụ thể (sửa bug, làm prototype…), do first/second mate sinh ra.
- Spin up: khởi tạo/khởi chạy một agent hoặc phiên mới.
- Route (định tuyến): chuyển yêu cầu tới đúng agent phụ trách.
- Herder: công cụ quản lý các phiên agent trên nhiều máy (ở đây: "local" là MacBook, "mini" là Mac Mini).
- Headless: máy chạy không gắn màn hình/chuột/bàn phím, chỉ điều khiển từ xa.
- Lavish board / artifact tương tác (interactive artifact): trang trực quan agent tạo ra để người dùng xem prototype, screenshot và chọn quyết định, rồi gửi phản hồi ngược lại cho agent.
- Prototype (nguyên mẫu): bản thử nhanh của một ý tưởng (ở đây là các loại chim mới) để chọn trước khi làm thật.
- Landed (đã merge vào code chính) vs. released (đã phát hành cho người dùng, ví dụ lên App Store).
- Harness: phần mềm "bọc" quanh model để chạy agent (Claude Code, Codex…).
- Relay (chuyển tiếp): bot trên Discord/X nhận mention rồi chuyển tin nhắn về phiên first mate local.
- Mention (@): gắn tên bot trong tin nhắn để gọi nó.
- Context window (cửa sổ ngữ cảnh): lượng token tối đa model "nhớ" được trong một phiên.
- Compact (nén ngữ cảnh): tóm tắt lịch sử hội thoại để giải phóng chỗ trong context window.

### Chỗ người mới dễ kẹt
- "Every second mate is a first mate" → về kỹ thuật, second mate là cùng một loại phiên agent như first mate, chỉ khác phạm vi được giao; nên bạn tương tác với nó y hệt first mate. Cấu trúc là cây: first mate → second mate → crewmate.
- Vì sao cần second mate → mỗi agent chỉ có một luồng chú ý và một context window; nếu first mate phải điều phối quá nhiều crewmate, nó sẽ bận và context đầy nhanh. Chia domain giúp giảm tải.
- Chạy agent trên máy khác (Mac Mini) → agent không cần màn hình; máy mạnh hơn chạy được nhiều phiên song song hơn. Công cụ như Herder giúp nhìn thấy/điều khiển phiên trên nhiều máy từ một chỗ.
- Relay từ Discord/X về phiên local → bot trên mạng xã hội chỉ là "cửa vào"; việc thực sự vẫn do phiên agent chạy trên máy của Kun làm. Lưu ý bảo mật: ai có thể mention bot thì có thể gửi yêu cầu tới agent — Kun không nói rõ cách giới hạn quyền ở đoạn này.
- "Landed but not released" → code đã vào nhánh chính nhưng chưa có bản phát hành mới cho người dùng; agent có thể so sánh lịch sử commit với bản phát hành để trả lời.
- Quy trình review prototype → người dùng không viết code; chỉ xem preview, chọn giữ/bỏ, rồi gửi phản hồi ngắn. Đây là điểm nghẽn duy nhất cần con người.
